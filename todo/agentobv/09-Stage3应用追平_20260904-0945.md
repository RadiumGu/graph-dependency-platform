## 三、⚠️ 最重要的发现：整体覆盖式移植会**静默移除观测埋点**

逐个冲突文件比对 X-Ray / OTel / Tracer / Activity 的引用数：

| 文件 | 本地 | 上游 | 判定 |
|---|---|---|---|
| `PaymentController.cs` | **22** | 10 | ⚠️ 移植会丢埋点 |
| `Startup.cs` | **4** | 0 | ⚠️ 移植会丢埋点 |
| `appsettings.json` | **2** | 0 | ⚠️ 移植会丢埋点 |
| `petstatusupdater/index.js` | **2** | 0 | ⚠️ 移植会丢埋点 |
| `SearchController.java` | 9 | **10** | ✅ 上游更多 |
| `PetFoodController.cs` | 17 | 17 | ＝ |
| `WebConfig.java` | 9 | 9 | ＝ |
| `application.yml` | 0 | 0 | ＝ |

全局上游更多（405 vs 371，因为代码总量大），但**逐文件本地在关键路径上更丰富**。

**这个项目的全部价值建立在那些埋点上** —— `etl_xray` 从 `GetServiceGraph` 建边，
埋点没了节点就从服务图里消失，图谱静默变残缺而无人报警。

### 因此定下的策略（有证据支撑，不需再议）

> **51 个非冲突的上游文件整体引入；15 个冲突文件逐文件合并，以「保留本地埋点 + 采纳上游功能」为原则。**

绝不整体覆盖冲突文件。

## 五、上游删改的三个服务：查证结论

**纪律见效**：单个关键词 grep 显示三个服务在上游 `microservices/` 下 0 文件，
换关键词全树搜索后发现**两个是挪走而非删除**。

| 本地服务 | 上游去向 | 处置 |
|---|---|---|
| `trafficgenerator`（.NET, 20 文件） | `src/applications/lambda/traffic-generator-node/` + `canaries/` —— **.NET 重写为 Node，容器改 Lambda/Canary** | **保留本地**（loadgen 已绕 ALB Cognito，天然合规；改 Lambda 会失去 EKS 内压测能力） |
| `petstatusupdater`（4 文件） | `src/applications/lambda/petstatusupdater-node/` | ✅ **已合并完成** |
| `petadoptionshistory-py`（7 文件） | **不存在** —— `microservices/` 0、`lambda/` 0、CDK 构造 0，三个角度都查过 | **保留本地** |

**关于 pethistory 的一个上游缺陷**：上游删了该服务，但 `petsite-net` 的
`PetHistoryController` **仍在调 `pethistoryurl`**（`/api/home/transactions`），
`payforadoption-go/README.md` 还写着「SQS → Triggers pethistory Lambda function」
而那个 Lambda 在 `src/applications/lambda/` 里**并不存在**。

即**上游留了一个悬空依赖 + 一份过期的 README**。所以保留本地 pethistory 不只是
「不想丢自己的东西」，而是**上游没有替代品，删掉会让 petsite 的 PetHistory 页面报错**。

## 六、已完成：`petstatusupdater`（1/6）

上游 `index.js` 把 X-Ray 埋点**去掉了**（改成裸 `new DynamoDBClient({})`），
但上游自己的 `package.json` 仍声明 `aws-xray-sdk-core`、`index.test.js` 里仍
`jest.mock('aws-xray-sdk-core')` 并 mock `captureAWSv3Client` ——
**上游内部不一致，不是可以照搬的现状。**

合并方案：**本地埋点为基线 + 采纳上游的显式依赖与测试**。

| 项 | 来源 |
|---|---|
| `captureAWSv3Client` 埋点 | **本地**（保留，并从 `aws-xray-sdk` 升到 `aws-xray-sdk-core` —— core 是不含 Express 中间件的轻量包，对 Lambda 正确，也是上游测试 mock 的那个） |
| `const` / 模板字符串 / 内联 `UpdateCommand` | **本地**（比上游的 `var` + 字符串拼接新） |
| 显式 `@aws-sdk/client-dynamodb` + `@aws-sdk/lib-dynamodb` 依赖 | **上游**（本地 package.json 缺这两个，靠 Lambda 运行时兜底） |
| `"test": "jest"` + jest devDependency + `index.test.js`（71 行） | **上游** |
| 记录 DynamoDB 返回的 `UPDATED_NEW` | **上游**（原实现只记入参，出问题分不清「请求发出去没生效」与「压根没发」） |
| Apache-2.0 license | **上游** |

**验证**：`npm test` → **3 passed**。上游的测试打本地保留埋点的实现，全过。
`captureAWSv3Client` 仍在（2 处命中），`node_modules` 已被 `.gitignore` 忽略。
